## 1. 一句话说清楚

> 在安路 **EG4S20BG256** 上，用**纯 RTL、零处理器**，做一个"插卡即播"的商业展陈终端：
> TF 卡里的 **640×480 24-bit BMP 图片**，经 `bmp_read` 解析、**一写双读 `frame_read_write`（含硬件 `WRITE_V_FLIP`）** 写入片内 8MB SDRAM；
> 读侧双通道锁步输出 A/B 两帧 24-bit RGB888 像素流，依次经过 **A/B 交叉溶解/滑动转场**、**亮度/对比度实时调节**、**多图层 OSD（64字中文滚动字幕 + 安路 Logo + 动态时间戳 + 参数回显 + 声波/频谱）**；
> **音频由 FPGA 片内实时多谐波波表合成**（支持 L1 测试音 / L2 旋律合成切换）；
> 最终用**一根 HDMI 线同时输出画面和声音**，QSPI 固化上电自启。

## 4. 关键机制详解

### 4.1 复用扩展的“一写双读”帧缓存（`frame_read_write_dual`）

为什么不用旧版 `Sdram_Control_4Port` 而复用 `frame_read_write`？
1. **位宽原生匹配**：`base` 中的 `sdram`（`sdr_as_ram`）和 `frame_read_write` 原生就是 **32-bit 数据位宽**（`{R,G,B,8'h00}`），而旧 `Sdram_Control_4Port` 硬编码为 16-bit 且用 `CS_N` 拆分半字；
2. **天然保留 `WRITE_V_FLIP=1`**：`frame_fifo_write` 内部自带按行倒退地址逻辑（`VFLIP_FIRST_ADDR_OFFSET` / `VFLIP_LINE_JUMP`），自动将标准自底向上的 BMP 翻正；
3. **改造成本极低、资源极省**：
   - 写侧（`wfifo_32_32_512` + `frame_fifo_write`）**一行不改**，继续由 `sd_card_bmp` 的 `write_buf_idx` 选择写入 `BUF0_ADDR (0)` 或 `BUF1_ADDR (307200)`；
   - 读侧例化两套完全相同的读缓冲：
     - **读通道 A**：`rfifo_a (rfifo_32_32_512)` + `frame_fifo_read_a`（固定读 `BUF0_ADDR = 0`）；
     - **读通道 B**：`rfifo_b (rfifo_32_32_512)` + `frame_fifo_read_b`（固定读 `BUF1_ADDR = 307200`）；
   - **锁步弹出**：在 `video_clk`（25MHz）域，两路读通道共用同一个 `video_read_req`（场同步脉冲）和同一个 `video_read_en`（`de_d[18]`），每帧严格同时弹出 307,200 个像素，天然保持 `(x, y)` 像素坐标 100% 对齐；
   - **125MHz 读突发仲裁**：当写通道不忙（`~App_wr_busy`）时，若 `rfifo_a` 或 `rfifo_b` 水位低于阈值（`wrusedw < 512 - 128`），仲裁器按轮询（或低水位优先）授权其中一路发起 128 字突发读，并将 `Sdr_rd_en` 路由至对应读 FIFO。

### 4.2 A/B 转场控制（`swap_ctrl` + 24-bit `transition`）

- 当 `sd_card_bmp` 完成新图片写入并切换 `disp_buf_idx`（如从 0 变为 1）时：
  - `swap_ctrl` 检测到目标显示缓冲变化，在下一个场消隐期（`vs` 上升沿）启动转场；
  - `alpha` 从 `0` 按步长（如每帧 `+8`，约 32 帧 ≈ 0.53s）递增至 `255`；
  - 定义 `src_rgb = prev_buf ? rd_rgb_b : rd_rgb_a`（旧图），`dst_rgb = cur_buf ? rd_rgb_b : rd_rgb_a`（新图）；
  - **模式 0（交叉溶解）**：对 R/G/B 三个 8-bit 通道分别计算：
    `out_ch = (src_ch * (255 - alpha) + dst_ch * alpha) >> 8`
  - **模式 1（水平平滑滑动）**：根据 `bound_x = (alpha * 640) >> 8`，左半屏 `x < bound_x` 显示新图 `dst_rgb`（或带分割高亮线），右半屏显示旧图 `src_rgb`。

### 4.3 多图层 OSD 叠加引擎（扩展 ① + ④ + ⑤）

在 `640×480` 画面上规划清晰的商业展陈四区叠加布局（画家算法优先级）：
1. **左上角角标区（Logo 层）**：叠加 `ANLOGIC 安路科技` 标识位图（如 `64×24`）；
2. **右上角状态与参数浮窗（扩展④ 信息叠加）**：使用 `8×16` ASCII 字库实时显示：
   - 运行时间戳：`TIME 00:05:23`（动态每秒更新）
   - 当前媒体与模式：`IMG:01/04 AUTO TR:FADE`
   - 实时显示参数：`BRT:+00 CNT:128 AUD:L2`（按键调节亮度/对比度时数值实时跳变）
3. **底部跑马灯字幕带（扩展① 动态字幕，`y ∈ [448, 463]`）**：
   - 半透明暗色底栏（底图 `RGB >> 1`）上叠加 **16×16 中文字库（64 字）** 标语，水平坐标 `x + scroll_x` 每帧平滑左移；
4. **音频律动可视化区（扩展⑤ 音频可视化，`y ∈ [380, 444]`）**：
   - **实时声波曲线（Waveform）**：利用 `640×8bit` 双口 RAM 缓存最近一帧音频波形，当扫描线 `|y - y_wave(x)| <= 1` 时渲染亮青色动态声波包络；
   - **8 段频谱能量柱（Spectrum Bars）**：在画面右下侧/底栏上方绘制 8 根带峰值保持与颜色渐变（绿→黄→红）的频谱柱。

### 4.4 板载多谐波波表音频合成（L1 / L2）

- **L1（测试音基线）**：保留 `hdmi_audio_tone_i2s_64fs` 音阶测试音，随时可通过按键切回验证基础要求③；
- **L2（主推：多谐波/双音伴奏波表合成）**：
  - 主声部（Melody）读取 `note_rom` 演奏完整乐曲旋律，采用 **基波 + 二次/三次泛音波表（或可切换正弦/三角/方波音色）** + ADSR 包络；
  - 伴奏声部（Bass/Chord）叠加低八度根音/分解和弦；
  - 合成后的 24-bit PCM 一方面经 `audio_mux` 送入 HDMI 1.4b 核内嵌输出（48kHz，ACR N=6144），另一方面直接旁路送给 `audio_viz` 做波形与频谱提取，实现零延迟音画律动。

## 5. 时钟与复位规划

| 时钟 | 频率 | 用途 | 来源 |
|:--|:--|:--|:--|
| `clk` | 50MHz | 矩阵键盘扫描、消抖、`regs`、数码管、POR 计数 | 板载晶振 R7 |
| `sd_card_clk` | 100MHz | `sd_card_top` / `bmp_read` / `sd_card_bmp` / 写 FIFO 写侧 | `sys_pll` C0 |
| `ext_mem_clk` | 125MHz | `sdram (sdr_as_ram)` / `frame_read_write_dual` 仲裁侧 | `sys_pll` C1 |
| `ext_mem_clk_sft` | 125MHz 180° | 片内 SDRAM 相位时钟 | `sys_pll` C2 |
| `video_clk` | 25MHz | 640×480 视频流水线、读 FIFO 读侧、OSD、音频可视化、HDMI 核 | `video_pll` C0 |
| `hdmi_5x_clk` | 125MHz | `hdmi_phy_wrapper` 10:1 DDR 串行时钟 | `video_pll` C1 |
| `audio_mclk` | 12.288MHz | L1/L2 音频发生器（`48kHz × 256`） | `PLL_HDMI_AUDIO` C2 |

> **时序收敛策略**：当前保持 `base` 复位结构快速推进 M1–M3 功能开发；在 **M4** 阶段统一为各时钟域添加双触发器异步复位同步释放桥（`reset_sync`），补齐 `timing.sdc` 的 `set_clock_groups -asynchronous`，并对 `frame_fifo_write.v` 的 `into_burst` 比较逻辑打一拍，彻底消除建立时间违例。

## 6. 存储与资源评估（基于实测精确核算）

### 6.1 片内 SDRAM（2M × 32bit = 8MB）

| 区域 | 起始字地址 | 长度（32-bit 字） | 用途 |
|:--|:--|:--|:--|
| 缓冲 0（帧 A） | `0x000000` (0) | 307,200 | `write_addr_0` / `read_a` 固定基址 |
| 缓冲 1（帧 B） | `0x04B000` (307,200) | 307,200 | `write_addr_1` / `read_b` 固定基址 |
| 空闲预留 | `0x096000` ~ `0x1FFFFF` | 1,482,752 | 充裕余量（仅用 29.3% SDRAM 容量） |

### 6.2 FPGA 逻辑、存储与 DSP 资源核算

基于 `hdmi_test/base/src/td_project/base_Runs/syn_1/base_gate.area` 的综合实测数据与扩展模块增量核算：

| 模块 | LUT | REG | BRAM9K (共64) | BRAM32K (共16) | DSP (共29) |
|:--|--:|--:|--:|--:|--:|
| **M0 `base` 已实现部分（实测）** | **3,775** | **3,669** | **18** | **0** | **0** |
| └─ 其中：HDMI 1.4b 核 + PHY + AXIS | 1,412 | 1,487 | 14 | 0 | 0 |
| └─ 其中：SD + `bmp_read` + `sd_card_bmp` | 1,144 | 814 | 0 | 0 | 0 |
| └─ 其中：单读 `frame_read_write` + `sdram` | 609 | 787 | 4 | 0 | 0 |
| └─ 其中：时序/彩条/L1音频/键盘/数码管 | 610 | 581 | 0 | 0 | 0 |
| **M1 增量：双读通道（`rfifo_b` + `read_b` + 仲裁）+ `swap_ctrl`** | +280 | +210 | +2 | 0 | 0 |
| **M2 增量：24-bit `transition` + `video_proc` + 多图层 OSD** | +1,080 | +460 | +3 | 0 | 9 |
| **M3 增量：L2 多谐波波表合成 + `audio_viz`（波形+8段频谱）** | +1,100 | +730 | +2 | 0 | 8 |
| **M1/M4 增量：16键 `regs` + 数码管全显 + 复位同步** | +200 | +180 | 0 | 0 | 0 |
| **全功能总计预估** | **≈ 6,435 (32.8%)** | **≈ 5,249 (26.8%)** | **25 (39.1%)** | **0 (0.0%)** | **17 (58.6%)** |

> **评估结论**：
> 1. **复用 `frame_read_write` 扩展双读极为划算**：仅新增 **224 LUT** 和 **2 块 BRAM9K**，总帧缓存子系统不到全芯片资源的 5%；
> 2. **片上 BRAM 绰绰有余**：全功能仅用约 25 块 BRAM9K（占 39.1%），16 块 BRAM32K 甚至完全未动用；
> 3. **LUT 与 DSP 安全可控**：总 LUT 约 33%，DSP 约 59%（17/29），布局布线拥塞度极低（当前 M0 Top 1% tile 拥塞仅 40.3%）。
