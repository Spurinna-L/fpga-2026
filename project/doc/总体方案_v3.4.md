# 总体方案 v3.4（M1 封档 + M2 行缓冲/转场/亮度/OSD）

> **状态**：M1 + 噪点补丁已封档（2026-10-25，tag `m1-final` / `m1-patch`）；M2 完整版（含 11 字滚动字幕）已实现/综合（2026-10-27，tag `m2-scroll`，待上板复测）
> **定位**：本文是项目的**唯一真源**（文件名 `总体方案_v3.4.md`；旧链接如仍指向 `v3.2`，请以本文件为准）。
> **v3.4 核心变更**：
> 1. 帧缓存最终定为 **`frame_read_write`（1 写 1 读，32-bit，`WRITE_V_FLIP=1`）+ 4 个 SDRAM 槽位**；
> 2. **开机只写、运行只读**：上电预载 4 张图，运行期切换只改槽号（双读引擎/乒乓加载/总线保护均废弃）；
> 3. M2 完整版（含字幕）时序：**Setup +0.508ns / Hold +0.003ns，0 失败端点**，LUT 5,082（25.93%）、BRAM9K 28、DSP 3；
> 4. 扩展要求的实现方式更新：转场改用 **行缓冲 + 行内寻址**（流式双 FIFO 做不到水平滑动）。

## 1. 一句话说清楚

> 在安路 **EG4S20BG256** 上，用**纯 RTL、零处理器**，做一个“插卡即播”的商业展陈终端：
> TF 卡里的 **640×480 24-bit BMP** 经 `bmp_read` 解析、由 `frame_read_write` 写入片内 8MB SDRAM 的 **4 个槽位**（含硬件 `WRITE_V_FLIP`）；
> **上电把 4 张图全部预载，之后运行期只读**：K1/轮播瞬间切换槽位；
> M2 起在只读通路上依次叠加 **A/B 转场、亮度/对比度、多图层 OSD（中文/Logo/时间戳/参数）**；
> **音频由 FPGA 片内实时合成**（L1 测试音 / L2 多谐波伴奏）；
> 最终用**一根 HDMI 线同时输出画面和声音**，QSPI 固化上电自启。

## 4. 关键机制详解

### 4.1 为什么是“单读 + 4 槽 + 分时”

**实测结论**（M1 调试，2026-10-25）：

- SDRAM 存储本身没问题：独占总线写 307200 字再读回，仅启动瞬间 4 字毛刺；
- **只要“显示读”和“帧写入”并发，控制器就会丢写**：某些地址保持旧内容，表现为静态横带，每次上电位置不同；
- 加 128 拍 burst 间隔保护无效 → 不是 burst 相邻问题，而是加密控制器内部的读写模式切换行为，RTL 层无法修复。

因此采用**按阶段分时**：

```
上电（约 1.2s）：扫描 4 张 BMP → 依次写入槽 0..3；期间 display_valid=0，不读帧缓存
运行期：         只读 SDRAM；K1/轮播只改 disp_buf_idx，下一帧边界换基址
```

- 槽位：`BUF0=0 / BUF1=307200 / BUF2=614400 / BUF3=921600`（4×307200 = 1.2M 字 < 2M）；
- 切换瞬间完成、无加载提示、无撕裂；
- 运行期没有任何写操作，并发问题从结构上消失。

**M1 补丁（闲置槽噪点）**：静止若干分钟后，闲置槽会出现稀疏固定噪点；实测自动刷新不足，且只有**顺序整段读**才算有效访问。新增 `sdr_refresh_sweep`，每帧消隐期顺序读 4 个槽，读数据不写显示 FIFO。
- **M1 实际扫描窗口**：`read_finish`（`v_cnt≈524`）至 `vs` 下降沿（`v_cnt=9`）共 `V_FP=10` 行（`320µs ≈ 40k` 字/帧），约 31 帧（`0.52s`）扫完 4 槽一轮，实测静止 15 分钟以上无噪点；
- **M2 扫描窗口扩展与排空约束**：
  - 按 `color_bar.v` 计数逻辑：`v_active` 在 `v_cnt==44 && h_cnt==15` 置起，但该行有效像素期间 `v_cnt` 已递增为 45，紧接着在 `h_cnt==160` 即进入首个有效像素，中间仅相隔 `145` 个 25MHz 周期（`5.8µs`），不足以完成首行 A+B 共 1280 字的读取（至少需 `10.24µs` + SDRAM 延迟）；
  - 因此 M2 的首行（`y=0`）预取**必须在 `v_cnt=44` 启动**（提前一整行，距首个有效像素约 `37.8µs`）；同理，最后一行（`y=479`）在显示第 478 行（`v_cnt=523`）期间即预取完毕；
  - 精确交接时序链：**`y=479 预取完成（v_cnt=523 内） → 启动 sdr_refresh_sweep → 到达 v_cnt=44（或满 150k 字）停止发 en → 排空 12~16 拍（保持 active=1） → 行读取接管预取 y=0`**（空闲窗口达 ~44 行 ≈ `1.4ms`，充裕容纳 `150k` 字/帧）。

> 为什么不用“运行期乒乓加载”：那正是横带的来源。为什么不用双读引擎：之前测试双读时未门控开机预载读请求导致写丢字，且流式双 FIFO 无法支持行内 `x` 偏移寻址（水平平推滑动）。

### 4.2 A/B 转场（M2，行缓冲）

```
SDRAM → frame_line_read（每行取 A 行 640 字 + B 行 640 字，连续 1280 字）
      → line_buf_A[2] / line_buf_B[2]（640×24 乒乓，2048×24 显式 BRAM9K，每个占 6 块、A/B 共 12 块；停用 rfifo 省 2 块，全片净增 10 块）
      → mixer：溶解 out = A + (((B - A) * α) >> 8)；滑动按 x 偏移选源
      → video_post（video_proc 亮度/对比度 + osd_composer/logo_overlay/scroll_text_overlay 组合）→ AXIS → HDMI
```

关键点与避坑准则：

1. **行缓冲提供行内任意寻址**，水平平推滑动（`A(x-dx)` / `B(x+640-dx)`）与任意 x 偏移才能实现；
2. **不按固定延时切换 A/B**：`frame_line_read` 连续发完整 1280 个 `App_rd_en`，计满 1280 个 `Sdr_rd_en` 返回才置 `line_done`，确保 A/B 两行全部落进行缓冲；
3. **单乘法器节省 DSP**：Alpha 混合写成 `out = A + (((B - A) * α) >> 8)`，三通道实测仅综合为 **2 个 DSP**，加 `video_proc` **1 个 DSP**，全片合计仅用 **3/29 个 DSP**；
4. **行缓冲 BRAM 账目**：每个 `line_buffer`（`2048×24` `EG_LOGIC_BRAM` PDPW 模式）占 6 块 `BRAM9K`，A/B 共 12 块；停用 `rfifo` 释放 2 块，净增 10 块，全片 `BRAM9K` 从 18 块变为 28 块（仍余 36 块 `BRAM9K` + 16 块闲置 `BRAM32K`）；
5. 每行 A+B 共 1280 字 = 10.24µs，行周期 32.0µs，读带宽翻倍后仍只占 125M 的 29.5%，转场期间全程**只读**；
6. **读命令必须连续发完整 1280 字，不因 `Sdr_busy` 中断**：实测中途暂停会把一行拆成不连续小段，控制器返回节奏变化导致行内像素错位（纵向梳齿/短横虚线）；与 M1 的 `frame_fifo_read` 一样连续发命令。

### 4.3 多图层 OSD（扩展 ① + ④ + ⑤）

优先级（画家算法，括号内为当前状态）：

1. **左上角 Logo**：安路标识 32×32 位图（✅ M2，`logo_overlay`）；
2. **右上角状态栏**（ASCII 8×16）：`TIME 00:00 IMG:1/4` / `BRT:+00 CNT:128 TR:0`（✅ M2，`osd_composer`）；
3. **底部滚动字幕**（`y ∈ [444,467]`）：白底红字 + 11 字 16×16 中文，逐帧左移，K13 开关（✅ M2）；
4. **音频可视化**（`y ∈ [376,439]`，与 `y=444` 字幕横幅留 4px 间距）：声波曲线（`640×8bit` RAM，用提前 1 拍列坐标 `d1_x` 寻址实现 0 额外流水延迟）+ 8 段频谱柱（⚪ M3）。

### 4.4 板载音频合成（L1 / L2）

- **L1**：`hdmi_audio_tone_i2s_64fs` 音阶测试音，可随时切回验证基础要求③；
- **L2**：`note_rom` + 基波/二三次泛音（或正弦/三角/方波音色）+ ADSR；低八度伴奏；
- 合成 PCM 一路进 HDMI 核（48kHz，ACR N=6144），一路旁路给 `audio_viz`，实现零延迟音画律动。

## 5. 时钟与复位

| 时钟 | 频率 | 用途 | 来源 |
|:--|:--|:--|:--|
| `clk` | 50MHz | 键盘/消抖/`regs`/数码管/POR | 板载 R7 |
| `sd_card_clk` | 100MHz | SD/BMP、写 FIFO 写侧 | `sys_pll` C0 |
| `ext_mem_clk` | 125MHz | 帧缓存 FSM、SDRAM | `sys_pll` C1 |
| `ext_mem_clk_sft` | 125MHz 180° | SDRAM 输出时钟 | `sys_pll` C2 |
| `video_clk` | 25MHz | 视频流水线、读 FIFO 读侧、HDMI 核 | `video_pll` C0 |
| `hdmi_5x_clk` | 125MHz | TMDS 10:1 DDR | `video_pll` C1 |
| `audio_mclk` | 12.288MHz | L1/L2 音频 | `PLL_HDMI_AUDIO` C2 |

**复位**：`rst_n` + PLL lock + ≈1.3ms POR → `por_done`；每域 `reset_sync`（异步置位/同步释放）。

**时序（M2 完整版，`m2_scroll_timing.rpt`）**：Setup **+0.508ns** / Hold **+0.003ns**，0 失败端点。关键说明：

1. 各域异步复位 → `reset_sync`；
2. `frame_fifo_write` 的 `into_burst` / `rdusedw` / `App_rd_busy` 打拍；
3. SDRAM DQ 硬核路径与官方 `lab_ex5_i2s` 同源，按厂商惯例 `set_false_path`；
4. `clk / sd / mem / video` 四域已在 `timing.sdc` Section `#4` 声明为异步；**M3 注意**：当前 Section `#3`（`audio_mclk` 异步组）尚未包含 `clk`，导致 STA 仍将 `clk -> audio_mclk`（`por_done_r -> u_rst_aud`）按 `1.334ns` 同步预算分析（得 `+0.508ns`）；**M3 将 50MHz `regs_audio_src` / `regs_timbre` 接入 `audio_mclk` 前，须在 `timing.sdc` 中把 `audio_mclk` 与 `clk` 声明为异步**（补齐后全片真实最差 Setup WNS 为 `sd_card_clk` 域内的 `+0.756ns`，而 `ext_mem_clk` 125MHz 域内 Setup WNS 达 `+1.541ns`）；
5. **Hold `+0.003ns` 来源**：位于 `u_hdmi` 加密核内部 `video_clk`（25MHz）复位同步释放路径（`removal` 检查），而 `ext_mem_clk`（125MHz）实测 Hold WNS 为 `+0.027ns`，因此无需对 `ext_mem_clk` 降频。
