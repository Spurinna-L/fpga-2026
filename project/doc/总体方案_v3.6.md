## 1. 一句话说清楚

> 在安路 **EG4S20BG256** 上，用**纯 RTL、零处理器**，做一个“插卡即播”的商业展陈终端：
> TF 卡里的 **24-bit BMP（源图 160×120~1920×1080）** 经 `bmp_read` 解析、`bmp_scale` 双线性适配到 **640×480**，
> 再由 `frame_read_write` 写入片内 8MB SDRAM 的 **4 个槽位**（含硬件 `WRITE_V_FLIP`）；
> **上电把 4 张图全部预载，之后运行期只读**：K1/轮播瞬间切换槽位；
> 运行期依次叠加 **A/B 转场、亮度/对比度、多图层 OSD（参数/Logo/11 字滚动字幕）**；
> **音频由 FPGA 片内实时合成**（L1 测试音 / L2 多谐波伴奏）；
> 最终用**一根 HDMI 线同时输出画面和声音**，QSPI 固化上电自启。

## 4. 关键机制详解

### 4.1 为什么是“单读 + 4 槽 + 分时”

**实测结论**（M1 调试，2026-10-25）：

- SDRAM 存储本身没问题：独占总线写 307200 字再读回，仅启动瞬间 4 字毛刺；
- **只要“显示读”和“帧写入”并发，控制器就会丢写**：某些地址保持旧内容，表现为静态横带，每次上电位置不同；
- 加 128 拍 burst 间隔保护无效 → 不是 burst 相邻问题，而是加密控制器内部的读写模式切换行为，RTL 层无法修复。

因此采用**按阶段分时**：

```
上电（当前 4 张 640×480 约 1.2s；含大图时更长）：扫描 4 张 BMP → 依次写入槽 0..3
                                                  期间 display_valid=0，不读帧缓存
运行期：只读 SDRAM；K1/轮播只改 disp_buf_idx，下一帧边界换基址
```

- 槽位：`BUF0=0 / BUF1=307200 / BUF2=614400 / BUF3=921600`（4×307200 = 1.2M 字 < 2M）；
- 切换瞬间完成、无加载提示、无撕裂；
- 运行期没有任何写操作，并发问题从结构上消失。

**闲置槽噪点（M1 补丁）**：静止若干分钟后闲置槽出现稀疏固定噪点；实测自动刷新不足，且只有**顺序整段读**才算有效访问。
新增 `sdr_refresh_sweep`，每帧消隐期顺序读 4 个槽（读数据不写显示 FIFO）。

- **M1 扫描窗口**：`read_finish`（`v_cnt≈524`）至 `vs` 下降沿（`v_cnt=9`）共 `V_FP=10` 行（`320µs ≈ 40k` 字/帧），
  约 31 帧（`0.52s`）扫完 4 槽一轮，实测静止 15 分钟以上无噪点；
- **M2 扫描窗口扩展与排空约束**：
  - 按 `color_bar.v` 计数：`v_active` 在 `v_cnt==44 && h_cnt==15` 置起，但该行有效像素期间 `v_cnt` 已为 45，
    紧接 `h_cnt==160` 即进入首个有效像素，中间仅 `145` 个 25MHz 周期（`5.8µs`），不足以完成首行 A+B 共 1280 字读取；
  - 因此首行（`y=0`）预取**必须在 `v_cnt=44` 启动**（距首个有效像素约 `37.8µs`）；最后一行（`y=479`）在显示第 478 行（`v_cnt=523`）期间即预取完毕；
  - 交接链：**`y=479` 预取完成 → 启动 `sdr_refresh_sweep` → 到 `v_cnt=44`（或满 150k 字）停止发 en → 排空 12~16 拍 → 行读取接管预取 `y=0`**（空闲窗口 ~44 行 ≈ `1.4ms`）。

> 为什么不用“运行期乒乓加载”：那正是横带的来源。为什么不用双读引擎：双读时未门控开机预载读请求会写丢字，且流式双 FIFO 无法支持行内 `x` 偏移寻址。

### 4.2 A/B 转场（M2，行缓冲）

```
SDRAM → frame_line_read（每行取 A 行 640 字 + B 行 640 字，连续 1280 字）
      → line_buf_A[2] / line_buf_B[2]（640×24 乒乓，2048×24 显式 BRAM9K，共 12 块）
      → mixer：溶解 out = A + (((B - A) * α) >> 8)；滑动按 x 偏移选源
      → video_post（亮度/对比度 + 参数 OSD + Logo + 滚动字幕）→ AXIS → HDMI
```

避坑准则：

1. **行缓冲提供行内任意寻址**，水平平推滑动与任意 x 偏移才能实现；
2. **不按固定延时切 A/B**：连续发满 1280 个 `App_rd_en`，计满 1280 个 `Sdr_rd_en` 返回才置 `line_done`；
3. **单乘法器省 DSP**：Alpha 写成 `A + (((B-A)*α)>>8)`，三通道实测 **2 DSP**，加 `video_proc` **1 DSP**，M2 全片 3/29；
4. **读命令必须连续发满 1280 字，不因 `Sdr_busy` 中断**：中途暂停会把一行拆成不连续小段，导致行内像素错位（纵向梳齿/短横虚线）。

### 4.3 预载图片缩放（扩展 ③，M3，已上板）

```
TF 原始扇区 → bmp_read（真实 W/H、跳行填充、源像素流 + src_sop 行首标志 + src_ready 反压）
            → bmp_scale（1024×25 FIFO[带行首标志] + 2×2048×24 行缓冲 + 双线性 + 补黑）
            → frame_read_write（固定 640×480，WRITE_V_FLIP=1，App_wr_sop 显式行对齐）
```

**规格**

- 源图 **160×120 ~ 1920×1080**、24bit、非压缩、bottom-up；`stride=(W*3+3)&~3`，行填充由 `bmp_read` 跳过；
- 输出固定 640×480：`DW/DH = min(640/W, 480/H)`，`OX/OY` 居中补黑边；
- **640×480 源图走逐像素旁路**，与 M2 画质完全一致；
- 双线性 8-bit 小数权重，11 拍/像素（离线缩放）；最后一行/列强制取源边界；
- 反压：FIFO 半满拉低 `src_ready`，`bmp_read` 在**扇区边界**暂停 `sd_sec_read`；
  加载器已收满 H 行后不再反压（源端剩余像素直接丢弃，避免"源端等 FIFO、加载器等输出"的死锁）；
- 资源：`bmp_scale` 占 15 块 BRAM9K（行缓冲 12 + FIFO 3）、7 DSP；全片 43/64 BRAM9K。

**行锁定（v3.6 新增，斜切根治的结构保证）**

链路里每一级都不再"数像素推断行边界"，而是**用源端给出的真实行首对齐**：

| 环节 | 机制 |
|:--|:--|
| `bmp_read` | 每个源行第一个像素额外输出 `src_sop`（由 `src_x==0` 判定，与像素同拍） |
| 源 FIFO | 宽度 24→**25**，`{src_sop, pix}` 一起穿过 FIFO，标志与像素永不错拍 |
| `bmp_scale` 装载器 | `src_sop` 到达即锚定行首；若该行源像素不足 W → 补黑补齐（`LD_PAD`）；超出 → 截断 |
| `bmp_scale` 旁路 | `out_sop` 直接取 `src_sop`（不再用计数器推断行宽） |
| `frame_fifo_write` | 数据 bit0 携带行首标志 → 行地址 = 上一行首 − 640，**与上一行实际收到多少字无关** |

效果：任一行丢/多几个像素，最多影响那一行，**不会逐行累积成斜线**（回归用例 `tb_scale_rowlock` 用"故意短 1 像素"的行验证）。

**验证**

`tb_bmp_read`（任意尺寸/行填充）、`tb_bmp_read_pad0gap`（**SPI 空拍 + 无行填充**，锁住 §7.1 的根因）、
`tb_bmp_scale`（1:1/2×/16:9/竖图/奇数宽）、`tb_scale_rowlock`（短行不漂移）、`tb_fb_sop`（行地址显式对齐）、
`tb_pad`（只送 306700 像素 → 仍输出 307200）、`tb_bmp_pipeline`（高速送数 + 反压）、
`tb_sd_bmp`（**真实 `sd_card_m3_a.img` 回放**：扫描 4 张 → 4×307200 字 → `display_valid=1`）。

| 时钟 | 频率 | 用途 | 来源 |
|:--|:--|:--|:--|

**复位**：`rst_n` + PLL lock + ≈1.3ms POR → `por_done`；每域 `reset_sync`（异步置位/同步释放）。

**时序（M3 主 bit，`project/out/m3_scale_timing.rpt`）**：Setup **+0.110ns** / Hold **+0.011ns**，0 失败端点。
M2 基线为 Setup +0.508ns / Hold +0.003ns。关键说明：

1. 各域异步复位 → `reset_sync`；`frame_fifo_write` 的 `into_burst`/`rdusedw`/`App_rd_busy` 打拍；
2. SDRAM DQ 硬核路径与官方 `lab_ex5_i2s` 同源，按厂商惯例 `set_false_path`；
3. `clk / sd / mem / video` 四域已在 `timing.sdc` Section `#4` 声明为异步；
   **`audio_mclk` 组尚未包含 `clk`**（M3 接 50MHz 音频参数前必须补上），当前 STA 把 `clk→audio_mclk` 按 `1.334ns` 同步预算分析；
4. 最差 Setup 在 `sd_card_clk`（100MHz）域内的 `bmp_scale` 数据通路；最差 Hold 在 `u_hdmi` 的 `video_clk` 内部路径；
5. 余量偏小（Setup 110ps / Hold 11ps，与 M2 的 3ps 同量级）：**每次改 RTL 必须复测时序**，偶发违例优先换 P&R seed，不要靠降频掩盖。

  - `audio_mclk` 与 `clk` 的异步组待补（接 L2 音频参数前）。

### 7.1 斜切根因与修复（2026-10-31，已上板确认）

**现象**：经 `bmp_scale` 适配的源图（含 1:1 的 640×480）出现**约 1.0~1.25 px/行**的斜切，
右缘可见重复段，斜分界线位置固定、每次上电一致；M2（无缩放）与片内图案自检均笔直。

**根因（唯一）**：`bmp_read` 的**字节相位寄存器在"行末字节到达之前"被清零**。

```verilog
// 旧: row_byte_cnt 一走到 stride-1 就清零相位 —— 此刻行末字节还没来
if (row_byte_cnt == row_stride_r - 1)  bmp_byte_idx <= 0;
```

真实 SPI 是 **8 拍才来 1 个字节**，所以行末必然有空拍；空拍期间相位被清零，等真正的行末字节到来时
被当作"像素第 1 个字节" → **该行最后一个像素丢失**。每行丢 1 个像素，内容就逐行左移 1 →
正好是 1 px/行 的斜切。

**为什么之前一直仿不出来**：仿真里的 SD 模型是**背靠背每个时钟来 1 个字节**（没有空拍），
这个 bug 只在有空拍时发作 → 所有仿真 PASS、上板必斜。这是本次排查最关键的教训：
**测试台必须模拟外设的真实时序（字节间隔）**，否则"仿真全过"没有意义。

**修复**

| 层次 | 改动 |
|:--|:--|
| 根因 | 相位改为"**行首字节强制归零**、其余只随有效字节推进"（`cur_phase`），行末字节不再被打断 |
| 结构加固 | `src_sop` 源行首标志 + 源 FIFO 加宽到 25bit + `bmp_scale` 行锁定/短行补黑 + `frame_fifo_write` 的 `App_wr_sop` 显式行对齐（见 §4.3） |
| 清理 | 删除全部临时诊断（`DEBUG_SEG`、`dbg_*` 计数器、数码管调试显示），数码管恢复参数显示 |

**回归用例（锁住根因，防复发）**

| 用例 | 场景 | 断言 |
|:--|:--|:--|
| `tb_bmp_read_pad0gap` | 4×3 源图、行宽 12B 无填充、**字节间插 3 拍空拍** | 像素 12/12、行首标志 3/3（旧逻辑：9 个像素、1 个标志） |
| `tb_scale_rowlock` | 16×8 源图，第 2/5 行各少 1 像素 | 输出 32 像素、8 行全装载、最后一行仍是源第 7 行颜色 |
| `tb_fb_sop` | 每 7 行多 1 个字 | 307200 字全部落在 `(479-row)*640+col`，地址错误 0 |

**排查过程中被否定/回退的假设**（留档，避免重走）：卡镜像字节（逐字节 EXACT）、SD 扇区多余字节
（512B/扇区）、写 FIFO 水位（burst 水位从 256 抬到 320 无变化）、VFLIP 写地址（仿真地址全对）、
帧缓存/行缓冲/mixer/HDMI（片内图案自检笔直）、SD 域时钟频率（降到 50MHz 仍复现）、
`rdusedw` 位宽与 `write_finish` 锁存（两者均非本问题原因，最终实现回到 `c4bbf66` 基线 + 本节修复）。
