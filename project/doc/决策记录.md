## 2. 已废弃方案对照表

| 废弃方案 | 现行方案 | 废弃原因（一句话） |
|:--|:--|:--|
| 旧 `Sdram_Control_4Port` + 16-bit RGB565 | `frame_read_write` + `sdr_as_ram`（32-bit） | 旧控制器硬编码 16-bit，不支持 BMP 逐行倒序写 |
| 720p + 16-bit + DVI 旧骨架（`legacy/`） | 640×480 + 24-bit + HDMI 1.4b | 分辨率/色深不符，且无音频 |
| **运行期双缓冲乒乓加载**（写非显示块，写完切换） | **开机 4 槽预载，运行期只读** | 写与显示读并发时控制器丢写 → 静态横带 |
| **双读引擎** `frame_read_write_dual` + `frame_fifo_read_arb` + `rd_arbiter` | 单读 + 4 槽（M2 用行缓冲实现 A/B） | 真实板上 A 通道有条带；根因未定位，且流式双 FIFO 无法做水平滑动 |
| **128 拍总线交接保护**（`wr_idle_cnt`/`rd_idle_cnt`） | 读写按阶段分时 | 实测不能消除丢写，说明不是 burst 相邻问题 |
| 运行期 K14 自检 / K15 总线模式 / K16 翻页 | 全部移除（源码保留） | 调试冗余，封档不参与综合 |
| 单音纯正弦波 L2 + 16 段 Goertzel | 多谐波/双音 + 声波曲线 + 8 段频谱柱 | 单音只有一根柱亮，视觉效果差且费 DSP |
| 仅静态标语 OSD | 64 字滚动 + Logo + 时间戳 + 参数回显 | 补齐评分要素 |

## 3. 关键结论（写给未来的自己）

1. **SDRAM 存储本身没问题**：独占总线写 307200 字再读回，仅启动瞬间 4 字毛刺。
2. **并发读写才会丢写**：显示读与帧写入同时在跑时，某些地址保持旧内容（静态横带，且重开一次位置会变）。
3. **加密控制器内部不可见**：不要试图用 RTL 打补丁绕过，直接按阶段分时即可。
4. **分时的代价可以藏起来**：把写放到开机 1.2s，用户只会看到一次“加载中”，运行期切换零延迟。
5. **M2 的硬约束**：运行期只读。转场 = 读两个槽，绝不写 SDRAM。
