# 素材与字库规范 v3.4

> 目标：让"图片素材 + 中文字库 + 安路 Logo + ASCII 参数图层"全链路可重复、可复现。

## 1. TF 卡 BMP 图片规范（硬性要求）

| 项 | 要求 | 说明 |
|:--|:--|:--|
| 文件格式 | **标准 Windows BMP** | 必须以 `"BM"` 开头，不可直接修改 JPG/PNG 后缀 |
| 分辨率（M2 bit `m2_scroll`） | **640 × 480** | `bmp_read.v` 硬性匹配 `width==640 && height==480` |
| 分辨率（M3 bit `m3_scale`） | **160×120 ~ 1920×1080** | 预载时经 `bmp_scale` 双线性适配到 640×480，保持比例 + 黑边 |
| 色深与压缩 | **24-bit RGB、非压缩（`BI_RGB=0`）** | `bit_count==24 && compression==0` |
| 存储行序 | **标准自底向上（Bottom-Up，高度为正数）** | `frame_fifo_write` 已开启 `WRITE_V_FLIP=1` 自动翻正；top-down 暂不支持 |
| 行对齐 | **每行 4 字节对齐** | `stride=(W*3+3)&~3`；奇数宽度有 1~3 字节填充，`bmp_read` 必须跳过 |
| 文件大小 | M2：`921,654` 字节；M3：随尺寸变化 | 例：1920×1080 = `54 + 1920×1080×3` 字节 |
| 数量与位置 | 最多 **4 张** | 按扇区先后顺序扫描，**依次预载到 SDRAM 槽 0..3**；槽号 = 打包顺序，不依赖文件名 |

### SD 卡制作工具链（推荐）

当前 RTL **不解析 FAT32**：`bmp_read` 从第 0 扇区起逐扇区扫 `"BM"`，
命中后按 `file_len` **连续读取**。所以每张 BMP 在卡上必须是连续扇区。

Windows 直接拖拽复制不保证连续；官方 `sync_to_sd.py` 也只是“顺序复制”，
不能保证碎片化卡上的连续性。推荐使用仓库自带的确定性打包工具：

```powershell
cd project\src\tools

# 1) PNG/JPG -> 24-bit bottom-up BMP
python bmp_convert.py input_images -o output_bmp

# 2) 校验（M3 缩放 bit 用默认范围；M2 bit 加 --strict-640x480）
python check_bmp.py output_bmp

# 3) 打包为 64MB 连续扇区镜像 + manifest
python sd_pack.py output_bmp -o output_sd\sd_card.img --sha256

# 4) 模拟 RTL 扫描，确认 4 张图都能找到
python sd_verify.py output_sd\sd_card.img --expect 4
```

然后用 **Win32DiskImager / balenaEtcher** 把 `sd_card.img` 写到 **物理 SD 卡**
（不是 `E:` 盘符）。写完后 Windows 若提示“需要格式化”，**不要格式化**。

> 工具细节与故障排查见 `project/src/tools/README.md`。
> 原始镜像不含 FAT32 分区；卡在 PC 上不可浏览，换图请重新打包。

## 2. OSD 图层字库与 Logo 规范

本系统 OSD 共包含 **3 类片内 ROM 素材**，当前**全部为组合 LUT ROM，0 BRAM**：

### 2.1 中文滚动字幕（实际实现：`font_cn_16x16`）

- **点阵规格**：`16 × 16`（每字 16 行 × 16 bit = 32 字节）；
- **实际容量**：**11 个汉字**（`逐逻辑而行，赴创新之约`，code 0~10），
  `11 × 16 × 16 = 2,816 bit`，组合 LUT ROM（**0 BRAM，0 拍延迟**）；
- **取模方向**：横向取模，每行 `bit[15]` 为最左像素，`bit[0]` 为最右像素；
- **生成工具**（`project/doc/tools/gen_cn_font_v.py`，不是旧版 `gen_font_mif.py`）：
  ```powershell
  python project\doc\tools\gen_cn_font_v.py --text "逐逻辑而行，赴创新之约" `
      --font "C:/Windows/Fonts/simsun.ttc" `
      --out  project\src\user_source\hdl_source\video\font_cn_16x16.v `
      --size 16 --preview
  ```
- **滚动模块**：`video/scroll_text_overlay.v`，底部 `y=444..467` 白色横幅 + 红色字，
  每帧左移 1px；K13 独立开关，默认开；
- **扩展说明**：脚本支持 1~16 个字。原规划的“64 字 / BRAM 字库”未启用；
  如果后续要换长文案，可扩展脚本或改用 BRAM 方案（需要同步 `TEXT_N` 与 1 拍流水）。

### 2.2 ASCII 字库（`font_ascii_8x16`）—— 参数回显
- **点阵规格**：`8 × 16` 标准可打印 ASCII（字符范围 `0x20`～`0x7F`，或精选 64 个常用数字/大写字母/符号）；
- **容量**：64～96 字符 × 16 行 × 8 bit = `1KB ~ 1.5KB`（**1 块 BRAM9K**）；
- **右上角实时叠加内容（实际 2 行 × 20 字符）**：
  - 第 1 行：`TIME 00:05:23  IMG:01/04`（`MM:SS` 每秒动态跳变，图片号随切图实时更新）
  - 第 2 行：`BRT:+00 CNT:128 TR:FADE `（亮度、对比度、转场模式、音源 `L1/L2` 随按键实时跳变）

#### 2.2.1 实际实现（M2 扩展④ 已落地）

文件 `project/src/user_source/hdl_source/video/font_ascii_8x16.v`：

- **只保留 32 个字符**（参数回显够用）：`0`~`9`、`:`、`/`、`+`、`-`、空格、`.`，
  以及字母 `T I M E B R C N G A F D S P O L`；
- **组合 LUT ROM**：`always @(*) case({I_code, I_row})`，
  ⇒ **0 块 BRAM，约 200 LUT**，且**组合读 → 与像素同拍，不需要额外延迟补偿**；
- **生成器**：`project/doc/tools/gen_ascii_font_v.py`
  ```bash
  python project/doc/tools/gen_ascii_font_v.py \
    --font "C:/Windows/Fonts/simsun.ttc" --size 16 --align fixed --dy 0 \
    --out project/src/user_source/hdl_source/video/font_ascii_8x16.v
  ```
  - **必须用 `--align fixed`**：按字形外框居中会让 `/ + .` 这类窄字形左右漂移；
  - 已验证 `simsun.ttc` @16px 出图最干净（`consola` 在 13/15px 会发虚）；
  - 可加 `--preview` 在终端打印点阵，先看效果再落地；
- **实际版面为 2 行 × 20 字符**（比规划窄，右侧仍留 8px 边距）：
  ```
  TIME 00:00 IMG:1/4
  BRT:+00 CNT:128 TR:0
  ```
- 中文滚动字幕已落地为 **11 字 LUT ROM**（`font_cn_16x16`），与这套精简 ASCII 字库共存，均 0 BRAM。

### 2.3 安路科技标识（`logo_rom`）—— 扩展① 多图层混合
- **规格**：左上角叠加 `ANLOGIC` 图形 + 文字标识（如 `96 × 24` 或 `64 × 24` 像素，支持 2-bit 4 色：透明 / 安路红 `#E60012` / 深蓝 `#0D1B5E` / 纯白 `#FFFFFF`）；
- **容量**：`64 × 24 × 2bit = 3,072 bits < 0.4KB`（可用分布式 LUT ROM 或 **1 块 BRAM9K** 实现）。

#### 2.3.1 实际实现（M2 已落地：`32×32` Logo 水印图层）

- **文件**：
  - `project/src/user_source/hdl_source/video/logo_overlay.v` — 叠加模块（组合，0 拍）
  - `project/src/user_source/hdl_source/video/logo_data_32x32.v` — 点阵 ROM（脚本生成，勿手改）
- **点阵规格**：`32 × 32`，每像素 16bit = `{opaque, r[4:0], g[4:0], b[4:0]}`（RGB555 + 1bit 不透明位）
  - `opaque = 1` → 输出 Logo 像素（`v8 = v<<3 | v>>2` 还原 8bit，误差 ≤ 2）
  - `opaque = 0` → 原像素**逐位直通**，因此透明区对背景图/A-B 转场中间帧零影响
  - 容量 `32 × 32 × 16bit = 16,384 bits`，**组合 LUT ROM，0 BRAM**
- **位置**：左上角 `X0 = 8, Y0 = 8`（改 `logo_overlay.v` 的 `localparam` 即可移动/贴边）
- **生成器**：`project/doc/tools/gen_logo_v.py`（白底抠图 → 反预乘 → 等比 LANCZOS 缩放 → alpha 反锐化 → 二值化 → 去孤立点 → RGB555）
  ```bash
  python project/doc/tools/gen_logo_v.py \
    --src "图片路径.png" \
    --out project/src/user_source/hdl_source/video/logo_data_32x32.v \
    --preview preview.png
  ```
  - **等比缩放**：`32×21` 内容上下居中放进 `32×32` 画布（不拉伸变形，上下各留透明边）
  - 白底会被转成透明，**不会**在画面上出现白方块；`--alpha-thresh`（默认 0.45）调粗细
  - `--preview` 会输出 8 倍放大 PNG + 终端 ASCII 点阵，先看效果再落地
- **挂载点**：`video_post.v` 中 `osd_composer` → `logo_overlay` → `rgb_out`，
  两级都是纯组合，**不改变原有的 2 拍流水对齐**（hs/vs 仍只延迟 2 拍）
- **开关**：与右上角参数面板**共用同一个按键** —— `K4`（`regs.osd_en`）。
  `video_post` 内部把已同步的 `prm_osd_en` 直接接到 `logo_overlay.I_en`，
  两个图层在同一帧边界同时开关，**没有**独立的 `logo_en` 端口了
- **资源实测**：`video_proc` + OSD + Logo 合计 +472 LUT；滚动字幕再 +244 LUT（全设计 4,838 → 5,082），**0 BRAM**；Hold +0.003ns
- **仿真**：`project/src/sim/tb_logo_overlay.v`，13834 项 0 错
  （覆盖 `en=0` 全直通、矩形外直通、`de=0` 直通、地址映射、ROM 结构自检）
