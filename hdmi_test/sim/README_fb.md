## 关键设计

### 1. 不算地址，用"流式"
`Sdram_Control_4Port` 的地址是**自动顺序递增**的：配置 `ADDR / MAX_ADDR / LENGTH`，
产生 `LOAD` 脉冲复位指针后，按顺序推/取即可。一帧恰好 W×H 个字 → 指针自动回绕、天然对齐。

### 2. 读侧要在"消隐期"预取
`video_timing_720p` 改为**从垂直消隐起步**，给读 FIFO ~30 行的预取时间；
否则有效帧头几个像素会**欠载**，且欠载会**少弹数据**导致整个序列错位。

### 3. 双缓冲换班
- `front`（像素域）决定读 RD1/RD2；`wr_buf`（写域）决定写 WR1/WR2，二者互补。
- 换班**只允许在垂直消隐期**（`vs` 有效）→ 绝不在扫描中途换 → **不撕裂**。
- 跨时钟域握手（单比特事件，toggle+同步+边沿检测）：
  - 写域 `frame_done` → 翻转 `swap_tgl` → 像素域 `pending`；
  - 像素域在 `vs` 期翻 `front`、置 `buf_ready`、翻 `ack_tgl` → 写域清 `busy`、翻 `wr_buf`。

### 4. 上电时序
`front=1`、`wr_buf=0`（第一帧写 A）；`buf_ready=0` 期间输出 `fallback_rgb`（测试图）。
第一帧写入并换班后 `buf_ready=1`，开始显示真实内容。

## 上板调试记录（Phase 6，真硬件）

上板后经历了一轮不小的排查，核心结论如下（**都是"模型没建模、只有真硬件才暴露"的坑**）：

| # | 现象 | 根因 | 修法 |
| :--- | :--- | :--- | :--- |
| 1 | 画面出现周期性竖条纹 / 左右微动 | 像素时钟用了 **75MHz（非标 60.6Hz）**，显示器做**重采样** | PLL 改成 **74.25/371.25MHz**（标准 720p60）：`REFCLK_DIV=10, FBCLK_DIV=3, CLKC0_DIV=99, CLKC1_DIV=20, CLKC2_DIV=4`（VCO=1485） |
| 2 | 图像整体偏移 **~半屏** | **每帧消隐期给读口 LOAD** → 把读指针推偏 | **读口只在初始化 LOAD 一次**（`RD_LD_FRM=0`），靠"自动回绕"对齐（同官方例程） |
| 3 | 图像整体偏移 ~330 像素 | 写指针随"突发粒度"漂移 | **每次换班给写口 LOAD**（对齐写指针） |
| 4 | 看起来"闪烁" | **帧标记每帧换颜色**（双缓冲正常换帧） | 正常现象，非 bug；正式素材无此现象 |
| 5 | 左边框比右边粗 | **显示器本身**（静态测试图同样如此） | 无视 |

**方法论教训**：
- `sdram_bhv` 行为模型必须**贴近真控制器**（突发粒度 + show-ahead 预取 + 寄存器输出），否则会出现"**仿真全过、上板却偏**"。第一版模型太理想（逐字读写、无突发），白白绕了弯路。
- 排查手段：`USE_FB`（旁路帧缓冲）、`led` 关键状态、`RD_LD_FRM`/`RD_PIPE`/`CHK` 开关逐一定位。

### 关键参数（真硬件推荐值）

```verilog
fb_mgr  : RD_LD_FRM = 0   // 读口只初始化 LOAD；每帧 LOAD 会推偏
          RD_PIPE   = 0   // 读 FIFO 是 show-ahead，0 拍
stub    : PACE = 1        // 写带宽足够；如需进一步降可调大
          MARK = 0        // 上板演示时关掉帧标记（否则看起来像闪）
```

### 已知小瑕疵（接真实图片时处理）

写口 LOAD 会清掉写 FIFO 里**帧末残留 <256 字** → 该帧末尾约 255 像素保留旧数据。
静态图看不出；接真实图片/转场时应改为"**等 `WRx_USE` 排空再 LOAD**"。

## 已知事项（上板注意）

- 行为模型的 `RD*_DATA` 是**组合输出（0 拍延迟）**；真控制器可能是**寄存器输出（差 1 拍）**，
  上板若图整体错位 1 像素，就在读侧补一拍流水。
- 写帧 18.4ms（50MHz）略慢于显示帧 16.7ms → 会**偶尔重复显示**（等下一帧写好的换班）。

## 调试记录（Phase 5 抓到的两个真 bug）

双缓冲首次验证时出现两类错误，都靠"dump 出 SDRAM 内容 + 逐像素比对"定位：

### Bug 1：写侧 off-by-one（帧末多吐 1 个像素）
- **现象**：帧 2（缓冲 B）整帧水平偏移 1 像素（标记落在 x=7..23 而非 8..23，错量≈12.5%）。
- **根因**：一帧结束那一拍，上游会多吐 1 个像素；而 `busy` 下一拍才生效，
  于是这个像素被写进了**旧缓冲**，导致**新缓冲少第 0 个像素**、整体左移。
- **修法**：`wr_stall` 加入 `frame_done`，帧末那一拍立刻暂停上游。

### Bug 2：读侧"陈旧预取"
- **现象**：某缓冲第一次显示时，开头 9~14 个像素是 `x`（未初始化内存）。
- **根因**：读口在**复位时就预取**了 FIFO，而那时缓冲还没被写。
- **修法**：每次**换班**对新前台读口再发一次 `LOAD`（消隐期用最新数据重新预取）。
